# 企业智能体平台功能拆解

状态：产品与架构基线（2026-07-29）

## 1. 文档目的

本文把企业智能体平台拆解为可建设、可验收的功能域。目标产品不是单一聊天页面，而是一套同时服务平台管理员、智能体开发者、业务运营人员和最终用户的管理与运行平台。

平台必须同时满足两类需求：

- 配置面：创建、组合、测试、发布和治理智能体及其依赖资源。
- 运行面：让同一个智能体安全地服务多个最终用户，并隔离每个用户的会话、记忆、运行结果和产物。

## 2. 用户角色

| 角色 | 主要职责 | 默认可见范围 |
| --- | --- | --- |
| 平台管理员 | 租户、模型网关、全局策略、系统健康、配额 | 全平台治理数据，不默认读取用户会话正文 |
| 租户管理员 | 租户成员、工作空间、审计、安全策略 | 本租户 |
| 工作空间管理员 | 智能体、Skill、工具、知识库、成员授权 | 指定工作空间 |
| 智能体开发者 | 配置、调试、评测和发布智能体 | 被授权的资源与测试数据 |
| 业务运营人员 | 查看运行质量、审批、任务和产物 | 被授权业务范围 |
| 审计人员 | 查看配置变更、授权和调用审计 | 只读、按审计授权范围 |
| 最终用户 | 使用已分配的智能体，管理自己的会话与产物 | 仅本人运行数据 |

`Identity` 表示 Workspace 中的一套业务角色智能体配置；“最终用户身份”表示实际使用者。一个 Workspace 可以包含多个 Identity，两者必须使用不同实体和字段，不能混用。


## 4. 详细功能拆解

### 4.1 租户、用户与权限

- 租户创建、启停、配额和数据保留策略。
- 用户登录、单点登录、服务账号和 API Key。
- 租户成员、工作空间成员、用户组和角色。
- RBAC：平台、租户、工作空间、资源和数据级权限。
- 最终用户到智能体的授权：按用户、用户组、组织或渠道分配。
- 数据访问审计：谁在何时读取、修改、导出或删除了什么。
- 管理员代查用户数据必须显式提权、记录原因并产生审计事件。

### 4.2 工作空间与环境

- 平台级 Workspace Blueprint：作为可复用的虚拟业务工作目录。
- Tenant 安装某个 Blueprint 版本后生成 TenantWorkspace。
- 一个 Workspace 内可以配置多个 Identity 业务智能体，也可以直接执行被允许的单个 Skill。
- 开发、测试、生产环境及不同环境的配置覆盖。
- Workspace Blueprint 维护标准 Skill、Identity、Tool、Prompt、Knowledge 和 Component 引用。
- TenantWorkspace 维护用户授权、Secret、配额、策略和租户定制覆盖。
- 只有开启定制功能的 Tenant 才能创建 Tenant-owned 资源版本或覆盖映射。
- 资源跨环境晋级，禁止直接用开发草稿覆盖生产版本。
- 导入、导出和迁移 manifest。

### 4.3 智能体中心

- 管理界面称为“智能体”，领域模型使用 `IdentityDefinition/IdentityVersion`。
- 智能体基本信息：名称、头像、描述、标签、负责人。
- 模型配置：模型 profile、温度、上下文长度、fallback 和预算。
- 对话配置：系统提示词、欢迎语、输入提示、兜底回复和常见问题。
- 能力绑定：Skill、Tool、知识库、Prompt、UI 组件和渠道。
- 行为配置：场景路由、最大轮次、确认策略、附件和产物能力。
- 调试台：模拟用户、输入上下文、查看计划、工具调用、Trace 和产物。
- 生命周期：草稿、评审、发布、停用、归档和回滚。
- 版本差异、引用关系、发布说明和精确版本导出。
- 使用授权：哪些用户或用户组可以使用哪些已发布版本。

### 4.4 Skill 中心

- Skill 包上传、目录扫描、Git/Registry 导入。
- `SKILL.md`、运行配置、输入输出 Schema、示例和引用文件检查。
- Skill 文件浏览、Schema 预览、依赖和允许工具清单。
- 版本、发布、归档、下载、升级和回滚。
- 引用查询：被哪些智能体、工作流和其他 Skill 使用。
- 权限预览、依赖预览、兼容性验证和回归测试。
- Skill 运行测试、样例集、成功率和版本质量对比。

### 4.5 工具与连接器中心

- Python、HTTP API、OpenAPI、MCP 和系统工具。
- 工具服务实体：Base URL、认证、网络范围、同步状态和负责人。
- OpenAPI 导入、刷新、operation 差异和异常提示。
- 操作级别名、描述、默认参数、输入输出 Schema 和扩展配置。
- 权限声明：网络、文件系统、密钥、数据域和写操作风险。
- workspace/智能体/用户级 allow、ask、deny。
- 超时、重试、熔断、幂等键、速率限制和成本。
- 沙箱、网络白名单、SSRF 防护和密钥最小注入。
- Tool 调试台、调用历史、错误率和延迟。

### 4.6 Prompt 中心

- 独立 Prompt 模板、变量 JSON Schema 和示例。
- System、Developer、Skill 片段、输出格式等类型。
- 草稿、版本、发布、归档和回滚。
- Prompt 渲染预览和敏感变量提示。
- 被智能体和 Skill 的引用关系。
- 评测集对比、模型兼容性和变更影响分析。
- 运行时记录模板版本和渲染摘要，不记录密钥或敏感原文。

### 4.7 UI 组件中心

- 声明式组件定义、版本和数据 Schema。
- 组件位置：欢迎区、常见问题、消息卡片、输入框上方、产物区等。
- 交互 action：打开详情、确认、重试、提交表单和下载产物。
- 智能体 slot 绑定及引用查询。
- 组件预览、Mock 数据和宿主能力兼容性。
- 引擎只输出结构化组件指令；Web、移动端或宿主业务系统负责渲染。

### 4.8 知识与记忆

- 知识库、数据源、文档、索引版本和同步任务。
- 数据源授权、文档 ACL 和检索结果来源。
- 召回、重排、阈值、引用和知识来源展示策略。
- 工作空间共享知识与用户私有知识分层。
- 会话短期记忆、用户长期偏好和业务项目记忆。
- 用户记忆查看、编辑、导出和删除。
- 记忆写入策略、过期策略、敏感信息过滤和审计。
- 向量索引必须包含租户、工作空间、智能体和用户命名空间。

### 4.9 模型与路由

- 多模型 provider 和 profile。
- 模型能力、上下文长度、价格、限额和健康状态。
- fallback、重试、熔断和路由规则。
- workspace/智能体级模型白名单和预算。
- 模型请求脱敏、用量、延迟、成本和失败统计。
- 模型变更评测、灰度和回滚。

### 4.10 渠道与接入

- Web Chat、SDK、API、嵌入式组件和第三方 IM 渠道。
- 渠道鉴权、回调签名和来源校验。
- 渠道用户与平台最终用户的稳定映射。
- 渠道能力声明：流式、附件、富组件、按钮和回调。
- 会话续接、重复消息去重和跨设备登录策略。
- 不同渠道不能通过可猜测 Session ID 读取其他用户会话。

### 4.11 会话与最终用户体验

- 会话创建、列表、重命名、归档和删除。
- 消息、附件、引用、工具状态、产物和错误恢复。
- 流式响应、断线重连和事件 cursor。
- 用户只能查看自己的会话、运行记录、记忆和产物。
- 管理侧默认只看指标与脱敏摘要；读取正文需要额外权限。
- 同一智能体服务不同用户时，上下文与历史不得相互复用。

### 4.12 工作流、任务与调度

- 串行、DAG、并行步骤和条件分支。
- 长任务入队、worker、取消、重试、超时和检查点。
- 定时任务、事件触发和人工触发。
- 幂等、失败补偿、死信和手动重放。
- 每个任务关联发起用户、授权快照、智能体版本和资源版本。

### 4.13 Run、Trace 与 Artifact

- Run 状态机、输入输出、错误、用量和资源快照。
- Trace 层级、模型调用、工具调用、策略判断和工作流步骤。
- Artifact 元数据、对象存储、预览、下载、保留期和清理。
- 按租户、工作空间、智能体、用户、Session 和版本查询。
- 全链路 request/run/trace correlation。
- 用户 Trace 只返回安全事件，不公开模型私有推理内容。

### 4.14 策略、审批与密钥

- 全局、租户、工作空间、智能体、用户组和用户级策略。
- 高风险工具 ask 审批、批准、拒绝、过期和撤销。
- 审批人范围、四眼原则和审批审计。
- Secret 引用、轮换、KMS/Vault 和使用审计。
- 密钥不能进入 Prompt、日志、Trace、Artifact 或前端响应。

### 4.15 评测、发布与质量

- 路由、结构化输出、工具选择、安全和业务质量评测集。
- 版本间离线对比、回归门禁和人工抽检。
- 灰度流量、A/B、回滚和发布说明。
- 按智能体/版本/模型/Skill/Tool 统计成功率、延迟、成本和用户反馈。
- 失败聚类、问题样本沉淀和重放。

### 4.16 运维与平台治理

- 系统健康、队列、worker、存储和 provider 状态。
- 结构化日志、OpenTelemetry、指标和告警。
- 租户、用户、模型、Tool、并发和成本配额。
- 数据备份、恢复、迁移、保留期和合规删除。
- 包签名、供应链审计和漏洞扫描。

## 5. 核心领域对象

```text
PlatformCatalog
└── WorkspaceBlueprint -> WorkspaceBlueprintVersion
    ├── SkillVersion references
    └── IdentityDefinition -> IdentityVersion
        ├── Skill/Tool/Prompt bindings
        └── Knowledge/Component bindings

Tenant
└── TenantWorkspace -> pinned WorkspaceBlueprintVersion
    ├── TenantCustomizationOverlay（可选）
    ├── TenantIdentity
    ├── Membership / Role / UserGroup / IdentityGrant
    └── EndUser
        └── AgentSession
            ├── Message / UserMemory
            └── Run -> TraceEvent / Artifact / Approval
```

平台标准配置以 Workspace Blueprint 为复用边界；租户配置和所有运行数据以 Tenant 为硬隔离边界；会话和用户记忆以最终用户为私有边界。

## 6. 分阶段交付

| 阶段 | 目标 | 核心交付 |
| --- | --- | --- |
| P0 | 安全管理基线 | 认证、租户/用户强隔离、RBAC、Workspace Blueprint、Identity/资源版本模型、审计骨架 |
| P1 | 可管理智能体 | 智能体配置与发布、Skill 管理、调试台、会话与 Run 管理 |
| P2 | 资源中心完善 | Tool Service、Prompt、Component、知识库、模型管理 |
| P3 | 可恢复运行 | PostgreSQL、对象存储、队列/worker、调度、断线恢复 |
| P4 | 平台化运营 | 评测、灰度、质量看板、成本、MCP/Channel、多智能体受控编排 |

P0 中的认证和用户隔离不是上线后的增强项，而是 Web 管理端与多用户使用的前置条件。

## 7. 平台级验收原则

- 任何请求都能确定 `tenant_id`、`tenant_workspace_id`、`principal_id` 和权限；平台模板管理请求必须具有平台作用域。
- 任何 Run 都能追溯智能体和依赖资源的精确版本。
- 同一智能体被两个用户使用时，两人的 Session、Message、Memory、Run、Trace 和 Artifact 互不可见。
- 所有管理写操作可审计，高风险执行可审批和恢复。
- 前端不拥有越权过滤责任；后端仓储查询和授权策略必须强制隔离。
- 本地开发适配器与生产适配器遵循同一领域和 API Contract。

层级与定制规则详见 [Tenant、Workspace 与 Identity 层级设计 ADR](../docs/ADR_企业智能体租户与Workspace层级设计.md)。
