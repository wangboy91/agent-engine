# 企业智能体平台现状对比与缺口

状态：基于当前工作区代码核对（2026-07-29）

## 1. 结论

当前项目已经具备“企业智能体执行内核”的主要骨架，但还不是可以直接开放给多个真实用户的企业智能体管理平台。

已经比较扎实的是 Skill/Tool 契约、执行循环、工作流、模型路由、Run/Trace/Artifact、Workspace/Identity、工具策略审批和 HTTP/CLI 接口。

最关键的缺口有四类：

1. 最终用户身份没有成为强制的数据隔离边界，存在会话串线和越权读取风险。
2. 没有可管理、可发布的 `IdentityDefinition/IdentityVersion`，当前 Agent 更接近一次运行时路由器。
3. 资源中心缺少完整生命周期：Prompt、Component、Tool Service、KnowledgeBase 以及统一版本/引用模型。
4. JSON/本地文件、无认证 HTTP、无队列和本地产物存储不能支撑生产级多租户 Web 平台。

## 5. 多用户隔离专项核对

当前代码不能保证“同一智能体给多人使用而不串线”，具体原因如下。

### 5.1 已有基础

- `RunContext` 有 `user_id/workspace_id/identity_id`。
- `AgentSession` 可以记录 `user_id`。
- Tool 执行上下文可以传递 `user_id`。
- Session 列表可按 workspace 和 identity 过滤。
- Agent 路由会按 workspace+identity 限制可用 Skill。

### 5.2 当前风险

| 风险 | 当前行为 | 后果 |
| --- | --- | --- |
| Session 所有权可被覆盖 | `ensure_session` 遇到同一 `session_id` 时会更新 workspace、identity 和 user_id | 知道或碰撞 Session ID 的请求可能改变归属并继续写消息 |
| Session 查询不校验用户 | `get(session_id)` 只按 ID 返回；列表不支持 user_id 过滤 | 用户可能读取他人会话 |
| Run 查询不按主体过滤 | RunStore `get/list` 没有 access scope | 可能读取他人输入、输出和错误 |
| Artifact 访问无授权 | artifact id/run id 查询没有用户所有权检查 | 可能下载他人产物 |
| Trace 订阅不够细 | 主要按 workspace/identity 过滤，没有最终用户强制过滤 | 同一智能体下可能收到他人运行事件 |
| 用户记忆未分区 | Memory 以 workspace+identity 为主 | 多个最终用户可能共享不该共享的长期上下文 |
| HTTP 无认证 | workspace/user 信息由请求提供，不是服务端认证主体推导 | 客户端可伪造作用域 |
| 本地 JSON 无并发事务 | 多请求读写同一文件 | 并发丢写和状态不一致 |

结论：当前 Workspace/Identity 是“资源可见性基础”，不是“最终用户内容隔离完成”。

## 6. 缺口优先级

### P0：Web 版和多人使用前必须完成

1. OIDC/JWT/API Key 认证与统一 `Principal`。
2. `tenant_id/workspace_id/principal_id/subject_user_id` 强制作用域。
3. Session 所有权创建后不可变；所有读取和写入都校验 owner。
4. Run、Trace、Artifact、Memory、事件订阅按最终用户强制过滤。
5. PostgreSQL repository 与 migration；关键表启用组合键、外键和可选 RLS。
6. RBAC、智能体使用 Grant 和数据访问审计。
7. `WorkspaceBlueprint/TenantWorkspace`、`IdentityDefinition/IdentityVersion` 与资源版本快照。
8. 越权测试：两个用户使用同一智能体，任何 ID 猜测都不能跨用户访问。

### P1：形成可用管理平台

1. 智能体创建、配置、调试、发布、停用和回滚。
2. Skill 多版本、发布、引用、文件和导出。
3. 会话、Run、Trace、Artifact 管理页。
4. 策略、审批、Secret 管理页。
5. 管理端角色和工作空间成员。

### P2：对齐完整资源中心

1. Tool Service/OpenAPI 同步中心。
2. Prompt 中心。
3. UI Component 中心。
4. KnowledgeBase 和用户私有记忆管理。
5. 模型 profile 管理。

### P3/P4：生产运营

1. 队列、worker、调度、对象存储和断线恢复。
2. 评测、灰度、质量与成本看板。
3. MCP/Channel、多智能体任务、包签名和供应链治理。

## 7. 推荐下一步

先实施 `multi-user-isolation-and-identity-registry` 变更包，把 Tenant、TenantWorkspace、认证主体、最终用户隔离、IdentityVersion 和资源快照一起定义。Web 管理端可以同时做只读页面骨架，但在 P0 验收通过前，不应开放真实多用户会话功能。

目标层级采用平台 Workspace Blueprint + TenantWorkspace 实例模型，详见 [Tenant、Workspace 与 Identity 层级设计 ADR](../docs/ADR_企业智能体租户与Workspace层级设计.md)。
