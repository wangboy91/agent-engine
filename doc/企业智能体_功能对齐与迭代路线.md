# 企业智能体功能对齐与迭代路线

状态：提案（2026-07-29）  
范围：基于当前 `bkl-skill-engine` 持续演进为企业业务智能体引擎；本阶段不建设企业智能体前端的 1:1 复刻。

## 1. 目标与边界

`企业智能体参考截图/` 呈现的是一个“智能体开发中心”：业务人员在同一控制台中管理智能体、Skill、工具服务、UI 组件和提示词，并把它们组合为可发布、可追踪的业务 Agent。截图中的招聘、员工发展等领域名称仅是业务示例，不是本引擎的领域边界。

本项目的目标形态是提供该中心背后的可嵌入运行内核：上层 SaaS、私有部署或业务系统通过 HTTP、SDK、CLI 或未来的管理控制台，创建并运行受治理的 Agent。

本轮遵循三条边界：

- 引擎负责资源契约、编排、执行、治理和可观测性；产品前端只消费管理 API 与运行事件。
- 业务流程不硬编码在 API/UI；它们进入 Skill、Tool、Identity 配置、场景映射或 Workflow 包。
- 多租户、权限、版本和审计必须贯穿资源管理与运行时，不能在上线前再补。

## 2. 截图提炼出的目标能力

| 企业智能体开发中心能力 | 截图证据 | 对 BKL 的引擎含义 |
| --- | --- | --- |

| Skill 中心 | Skill 列表、详情、核心指令、文件列表、引用、历史版本、下载 | Skill 包的版本化发布、不可变快照、依赖/引用关系、审核与回滚。 |
| 工具服务管理 | 工具服务（Base URL）及其 OpenAPI 工具列表、工具别名、请求参数、扩展配置、刷新 | 工具服务连接器、OpenAPI 同步、操作级 Tool 定义与环境/身份级配置覆盖。 |
| 组件管理 | 欢迎语、卡片、打开详情页等组件，支持查看引用 | 渲染无关的 `ComponentDefinition` 与位置绑定；引擎把组件作为结构化 UI 指令/事件输出。 |

| 对话与执行面 | 对话侧栏显示步骤与结果；业务页面展示 Agent 生成内容 | 对话 Session、流式事件、Run/Trace、产物与人工审批；支持把结构化结果回填到宿主业务系统。 |
| 知识、任务和产物 | Agent 可挂知识库、定时任务、任务列表、附件/产物、思考过程 | 知识检索端口、调度任务、Artifact 元数据和脱敏的执行可视化。 |
| 平台底座 | 架构图包含编排、Agent 编辑、Skill Hub、连接器、MCP、模型/安全/本体/RAG | 分层的领域模型、策略与密钥边界、模型网关、知识端口、MCP/Channel adapter 和异步任务。 |

## 3. 当前基线与差距

现有 `SkillEngine` 已是可用的执行内核：Skill/Tool 包加载及 Schema 校验、模型路由、Tool calling、串行/DAG Workflow、Agent 路由和输入补齐、Workspace/Identity、Tool allow/ask/deny 与审批恢复、Session、Run/Trace/Artifact、HTTP/SSE/WebSocket 均已存在。当前测试基线见 [当前能力评估与上线路线](当前能力评估与上线路线.md)。

下表用于决定增量建设顺序。

| 目标领域 | 现有基础 | 主要缺口 | 迭代策略 |
| --- | --- | --- | --- |
| Identity 定义 | `AgentLoop`、Session、Workspace/Identity、场景映射 | 没有持久化且可发布的 Identity 配置/版本；配置与运行态未显式分离 | 新增 `IdentityDefinition`、`IdentityVersion`、资源绑定与发布规则。 |
| Skill 生命周期 | 本地包、catalog、enabled 开关、JSON Schema | 没有草稿/审核/发布/归档、版本快照、依赖图与回滚 | 建立 Package Registry 与不可变版本记录。 |
| Tool/连接器 | Python、HTTP、OpenAPI importer、Policy/Secret | 没有工具服务实体、OpenAPI 同步状态、环境配置覆盖、网络生产治理 | 建立 Connector/ToolService；在生产化前补 SSRF、白名单、沙箱。 |
| Prompt | Skill 的 `SKILL.md` 与运行配置 | 没有独立 Prompt 资源、变量 Schema、版本和引用审计 | 建立 PromptTemplate，先支持 Agent System Prompt 和 Skill 片段引用。 |
| Component | 已可返回结构化输出/Artifact | 没有组件注册、slot 绑定、版本和宿主渲染协议 | 只定义声明式 UI Contract，不在引擎中实现页面渲染。 |
| Knowledge | MemoryStore/KnowledgeRetriever 端口与本地实现 | 缺知识库资源、索引任务、检索配置、来源权限 | 先定义契约与审计，再接向量/企业知识库适配器。 |
| 任务/异步 | DAG、Run、恢复审批 | 缺 durable queue、取消、调度、幂等与重试策略 | 先抽象 Job/Schedule，再引入 worker/队列。 |
| 多租户生产化 | Workspace JSON Store、Policy、Secret 引用 | 缺 OIDC/RBAC、DB 事务、KMS、对象存储、审计/指标 | 作为 Agent 管理面开放前的前置门槛。 |

## 4. 目标领域模型

```text
PlatformCatalog
└── WorkspaceBlueprint@version
    ├── IdentityDefinition ── IdentityVersion
    ├── SkillPackage ── SkillVersion
    ├── ToolService ── ToolOperation@version
    ├── PromptTemplate ── PromptVersion
    ├── Component ── ComponentVersion
    └── KnowledgeBase

Tenant
└── TenantWorkspace ── pinned WorkspaceBlueprint@version
    ├── TenantCustomizationOverlay（可选）
    ├── TenantIdentity
    └── User / Session / Memory / Run / Trace / Artifact

AgentSession -> AgentTurn -> Run -> TraceEvent / Artifact / Approval
Schedule -> Job -> Run
```

关键约束：

- `Definition` 是稳定业务标识，`Version` 是不可变内容快照；仅 Published 版本可被正式 Agent 绑定和运行。
- Run 必须记录 Agent、Skill、Tool、Prompt、Component、模型 profile 的精确版本及配置快照，以支持重放和审计。
- 引用必须可查询：删除/归档资源前先检查被哪些 Agent/Skill/组件绑定；运行中的版本不可修改。
- Workspace Blueprint 是可复用业务模板；Tenant 是所有可变配置、密钥、会话、记忆、Run、Artifact 与授权规则的强制隔离根。
- Component 仅描述 `slot`、数据 Schema、交互 action 和渲染提示；宿主应用负责具体 React/Vue/原生实现。

## 5. 分阶段路线图

### P0：资源模型与可发布目录（先做）

目标：让现有本地包从“文件夹可运行”演进为“可管理、可追溯的资源版本”，不改变 `SkillEngine` 的直接运行兼容性。

- 定义 Agent、Skill、Tool、Prompt、Component 的领域 Schema、版本状态和引用关系；新增 ports 与内存/JSON 实现。
- 将当前 catalog 扩展为 package source + version manifest；保留已有本地注册命令作为导入入口。
- 新增发布校验：Schema、依赖、Tool policy preview、资源引用、模型 profile、workspace 授权。
- 新增管理 API：资源列表/详情、创建草稿、发布、归档、版本列表、引用列表、导出 manifest。
- 为 `RunContext` 增加 `tenant_id`、`tenant_workspace_id`、`identity_version_id` 和 `resource_snapshot`；Trace 记录解析后的资源版本。

验收：同一 Skill 的两个已发布版本可并存；Agent 只能运行绑定版本；任意历史 Run 能反查完整资源快照和依赖版本。

### P1：Identity 配置与 Agent 执行编排

目标：形成截图中“智能体配置页”对应的引擎 API，而不是在业务系统拼散乱参数。

- 实现 Agent 基本信息、模型参数、系统提示词、欢迎语/兜底回复、输入提示、渠道能力、Tool/Skill/Knowledge 绑定。
- 将 AgentLoop 重构为可持久化状态机：路由、补充输入、确认、计划、执行、观察、答复；支持 `WaitingUserInput`、`WaitingApproval`、`Cancelled`、`Completed`。
- 定义 Agent 输出协议：文本、结构化数据、组件 slot 指令、artifact、宿主 action proposal。
- 把现有 Scene Mapping 纳入 IdentityVersion，支持确定性场景优先、LLM 路由 fallback 与路由评测。

验收：通过一个 Identity 配置即可完成“对话 → 调用指定 Skill/Tool → 流式事件 → 结构化结果/组件指令”的闭环；无须在 HTTP handler 硬编码业务流程。

### P2：Tool Service、Prompt 与 Component 中心

目标：覆盖截图中的三类可复用资源，并把运行时授权与资源配置分层。

- `ToolService`：保存 OpenAPI 来源、认证引用、同步时间和操作清单；导入/刷新生成不可变 Tool 版本，并允许 workspace/identity 配置别名、默认参数与扩展元数据。
- `PromptTemplate`：支持变量 JSON Schema、版本、引用、渲染审计；Skill 的核心指令仍保留在 Skill 包，复用片段通过显式引用组合。
- `Component`：支持 component contract、输入数据 Schema、slot、引用关系；Agent 输出 `ui_component` 事件，运行控制台先提供最小 JSON 预览。
- 强化 Tool 安全：网络目标白名单、OpenAPI SSRF 防护、受限 Python runner、secret 最小注入、调用配额和幂等键。

验收：OpenAPI 工具服务可安全同步并被 Agent 绑定；修改别名/默认参数不会修改 Tool 原始版本；组件与提示词均能查到引用和历史版本。

### P3：知识、调度与可恢复异步执行

目标：支持企业 Agent 的长期运行与知识增强。

- 将 KnowledgeBase 实体接入现有 `KnowledgeRetriever` port：数据源、索引版本、召回配置、来源权限与引用追踪。
- 增加 Job、Schedule、Worker ports；Run 支持排队、取消、超时、重试、检查点和恢复。
- 完善 Artifact：对象存储适配器、元数据、保留期、鉴权下载和业务回填回调。
- 完善 Session：事件 cursor、断线重连、历史任务/产物列表、脱敏的思考/决策摘要。

验收：API 进程重启后可查询/恢复长任务；定时任务能够创建可审计 Run；知识检索结果带来源且遵守 workspace 权限。

### P4：生产化与平台扩展

目标：使管理面可安全服务多业务线和多租户。

- PostgreSQL + migration 替换 JSON 作为服务端主存储；对象存储替换本地 Artifact 文件；KMS/Vault 替换本地 secret 存储。
- OIDC/JWT、RBAC、审计日志、租户/用户/模型/Tool 维度配额；OpenTelemetry、指标、告警、成本归因。
- 包签名、审核流、灰度发布、回滚、评测集和运行质量看板。
- 接入 Channel/MCP adapter 和受控的多 Agent `AgentTask` 编排；任何跨 Agent 调度都经过 PolicyEngine。

验收：多实例部署下资源版本、审批和 Run 状态一致；不同 workspace 的资源、密钥、会话和产物不可越权访问；可按版本、模型、Tool、Agent 查询质量、失败率与成本。

## 6. 首个落地变更包建议

建议下一次实施使用一个聚焦变更包：`tenant-workspace-identity-registry`。不同时开 UI、知识库、队列和多 Agent，避免把基础资源模型做成一次性大改。

交付清单：

1. `WorkspaceBlueprint/TenantWorkspace`、`IdentityDefinition/IdentityVersion`、`ResourceReference`、生命周期状态与版本快照的 domain schema；
2. Identity 与 Skill 版本绑定、Tenant 安装和定制覆盖的 repository port、内存和 JSON adapter；
3. 资源发布/归档/引用查询 application use case 与 FastAPI/CLI API；
4. `RunContext`、Run/Trace 中的资源版本快照；
5. 对应单元、API、回归测试与一个“员工发展专家”式的通用示例资源（不绑定招聘领域）；
6. API contract 文档与迁移说明。

完成该包后，再以同一版本/引用框架增加 ToolService、Prompt 和 Component，不重复设计生命周期。

## 7. 不在当前阶段做的事情

- 不复刻截图中的完整后台页面、租户视觉或具体 HR 业务流程；先稳定 API 与事件 Contract。
- 不允许任意用户上传并执行 Python Tool；Tool 安全隔离完成前仅运行受信任、审查过的包。
- 不将“展示思考过程”实现为输出模型完整推理；仅提供脱敏的计划、工具调用和决策摘要。
- 不先做无边界多 Agent 群聊；先保证单 Agent 的资源版本、状态恢复、权限和 Trace 可靠。
