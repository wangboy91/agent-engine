## 4. 初始化与登录

**账号在独立服务 `account-service/`（端口 8001）；基座只认 Bearer / 头桩。**

```bash
# 账号服务
cd account-service
uv sync
uv run python -m app.interfaces.scripts.seed_users
uv run account-service
# http://127.0.0.1:8051

# 智能体基座
cd engine
uv run ae serve --host 127.0.0.1 --port 8050 --config agent.yaml
# http://127.0.0.1:8050

# 前端（代理：/account→8001，/api→8000）
cd web
npm run dev
```

```bash
# 登录（账号服务）
curl -s -X POST http://127.0.0.1:8051/auth/login \
  -H 'content-type: application/json' \
  -d '{"username":"ws.admin","password":"WsAdmin@123"}'

# 用 token 调基座
curl -s http://127.0.0.1:8050/api/v1/me/identities \
  -H "Authorization: Bearer <access_token>"

# 改密（账号服务）
curl -s -X POST http://127.0.0.1:8051/auth/change-password \
  -H 'content-type: application/json' \
  -d '{"username":"ws.admin","old_password":"WsAdmin@123","new_password":"NewWs@12345"}'
```

## 5. 建议测试剧本

1. **管理员闭环**：`ws.admin` 登录 → 设置确保租户/工作空间 → 创建 Identity → 发布 → Grant `all-staff`
2. **员工可见性**：`user.gu` 登录 → `/me/identities` 应看到已授权智能体
3. **双用户隔离**：`user.gu` 建会话；`user.ye` 用对方 session_id 访问 → 404
4. **角色差异**：`dev.lin` 无发布权；`audit.zhou` 无写配置
5. **改密**：`change-password` 后旧密码 401，新密码可登录；DB 中无明文

## 6. 实现位置

- **独立服务**：`account-service/`（登录、用户、identity_links）
- 哈希：`account-service/app/passwords.py`
- Token：`account-service/app/tokens.py`（与基座共用 secret）
- 基座：只校验 Bearer / 头桩，**不再提供 /auth/login**
- Seed：`uv run python -m app.interfaces.scripts.seed_users`（在 account-service/）

## 7. 与业务账号的关系

生产：

1. 业务系统 / 企业 IdP 负责登录与员工主数据；
2. 基座校验 JWT 或可信网关头，映射 `principal_id`；
3. 「能否使用智能体」仍由基座 `IdentityGrant` 决定；
4. 本地 `auth_users` 仅保留平台/租户运维账号，或整体关闭。

详见 [账号与业务系统接入](账号与业务系统接入.md)。
