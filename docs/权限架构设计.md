## 1. 设计目标

本基座是 **多租户 SaaS 智能体执行与管理平台**，权限架构必须同时满足：

| 目标 | 含义 |
| --- | --- |
| 平台可运营 | 平台方能管理模板、租户、模型网关与全局策略，但不默认窥探租户用户正文 |
| 可复制业务 | 标准能力以 Workspace Blueprint 复用，多企业安装同一模板 |
| 企业可扩展 | 开启定制后，企业可在租户内覆盖/扩展，且不污染平台模板 |
| 员工可安全使用 | 最终员工只使用被授权智能体，数据与他人强隔离 |
| 可审计可追责 | 关键读、授权变更、审批、导出均可追溯到 Principal |

**一句话原则：**

> **身份先于资源，租户先于查询，角色管动作，所有权管数据；前端不拥有越权过滤责任。**

## 2. SaaS 权限总览（四层视图）

```text
┌─────────────────────────────────────────────────────────────────┐
│ L0 平台层 Platform                                                │
│   平台管理员 / 平台运营 · WorkspaceBlueprint · 模型网关 · 租户开通   │
└────────────────────────────┬────────────────────────────────────┘
                             │ 安装 Blueprint → 生成 TenantWorkspace
┌────────────────────────────▼────────────────────────────────────┐
│ L1 租户层 Tenant（硬隔离根）                                       │
│   企业管理员 · 成员/角色 · 配额 · 审计范围 · 定制开关                 │
└────────────────────────────┬────────────────────────────────────┘
                             │ 授权进入工作空间
┌────────────────────────────▼────────────────────────────────────┐
│ L2 工作空间层 TenantWorkspace                                     │
│   空间管理员 / 开发者 / 运营 / 审计 · Identity/Skill/Tool 配置       │
└────────────────────────────┬────────────────────────────────────┘
                             │ IdentityGrant → 最终用户
┌────────────────────────────▼────────────────────────────────────┐
│ L3 最终用户层 EndUser（员工）                                      │
│   仅本人 Session / Message / Run / Artifact / UserMemory          │
└─────────────────────────────────────────────────────────────────┘
```

与经典 SaaS IAM 对齐：

| SaaS 概念 | 本平台实体 |
| --- | --- |
| Organization / Account | `Tenant` |
| Project / Workspace | `TenantWorkspace` |
| Product Template / Catalog | `PlatformCatalog` + `WorkspaceBlueprint@version` |
| User / Identity（登录主体） | `Principal`（user 或 service_account） |
| RBAC Role | 平台角色 + 租户角色 + 工作空间角色 |
| Resource Policy | Tool Policy（allow/ask/deny）+ 数据所有权 |
| Subscription / Entitlement | `Tenant.features` + 配额 + `IdentityGrant` |

## 3. 主体模型（Principal）

所有请求必须从**已验证凭证**构造不可伪造主体，禁止信任 body 中的 `user_id` 作为访问主体。

```text
Principal
├── tenant_id                 # 当前租户（平台管理请求可用 platform scope）
├── principal_id              # 稳定用户/服务账号 ID
├── principal_type            # user | service_account | platform_operator
├── workspace_roles[]         # 例：ws_admin / developer / operator / auditor
├── group_ids[]               # 用户组，用于批量 Grant
├── scopes[]                  # 平台级 scope，如 platform.catalog.write
├── auth_session_id           # 登录会话，用于吊销
└── claims.extra              # impersonation、mfa、auth_time 等
```

### 3.1 凭证类型

| 凭证 | 适用 | 说明 |
| --- | --- | --- |
| OIDC / JWT（SSO） | 企业员工、管理员 | 短时 token + refresh；含 tenant 与角色声明或可查询 |
| Session Cookie | Web 控制台/工作台 | 绑定 auth_session_id，可撤销 |
| API Key / PAT | 服务账号、自动化 | 绑定 tenant + scopes + 过期；可轮换 |
| 管理员临时提权 | 代查用户数据 | 需 reason + 限时 + 审计事件 |

### 3.2 身份 vs 业务智能体

| 概念 | 是什么 | 不是什么 |
| --- | --- | --- |
| `Principal` / EndUser | 登录的人或服务账号 | 不是智能体 |
| `Identity`（产品名「智能体」） | 业务身份智能体配置 | 不是最终用户账号 |
| `AgentSession` | 某用户与某 Identity 的运行会话 | 不是登录 Session |

混用这两类「身份」是串线与越权的高发源，领域字段必须分开命名。

## 4. 角色体系（按四维度）

角色 = **角色定义（Role）** × **作用域（Scope）** × **权限集（Permission）**。  
同一人在不同 Tenant/Workspace 可有不同角色；跨租户默认不可见。

### 4.1 角色总表

| 维度 | 角色 | 典型岗位 | 作用域 | 能做什么 | 明确不能做什么 |
| --- | --- | --- | --- | --- | --- |
| **平台** | `platform_admin` | 平台负责人 | 全局 | 租户开通/停用、全局策略、模型 Provider、系统健康、配额模板 | 默认读取租户用户会话正文；随意改租户业务配置 |
| **平台** | `platform_operator` | 平台 SRE/运营 | 全局只读+运维 | 健康、队列、告警、租户级指标 | 业务配置写、用户正文 |
| **平台** | `platform_catalog_admin` | 平台产品/架构 | 平台目录 | 维护 WorkspaceBlueprint、标准 Identity/Skill 版本发布 | 代入租户生产数据 |
| **智能体开发** | `tenant_admin` | 企业 IT/管理员 | 本 Tenant | 成员与角色、工作空间创建、审计查看、定制开关、Secret 策略 | 跨租户；未提权读员工正文 |
| **智能体开发** | `ws_admin` | 业务空间负责人 | 某 TenantWorkspace | 空间成员、资源启停、发布检查、用户授权、策略 | 平台模板修改；其他工作空间 |
| **智能体开发** | `agent_developer` | 智能体开发者 | 被授权资源 | 草稿配置、调试、评测、提交发布 | 直接改生产已发布版本；读无关用户生产正文 |
| **智能体开发** | `operator` | 业务运营 | 运行与审批范围 | Run/质量视图、审批（按策略）、任务与产物治理 | 改 Identity 定义；平台/租户成员管理 |
| **智能体开发** | `auditor` | 审计/合规 | 审计范围只读 | 配置变更、授权、数据访问审计 | 任何写操作；默认无正文 |
| **企业扩展** | `customization_owner`（可选角色，可由 tenant_admin 兼任） | 企业定制负责人 | 本 Tenant 定制层 | 创建 Tenant-owned 覆盖版本、对比平台 diff、申请升级 | 修改平台 Blueprint；关闭隔离 |
| **企业员工** | `end_user` | 员工/业务用户 | 仅本人数据 + 已授权 Identity | 会话、任务、产物、本人记忆 | 任何管理配置；他人会话；内部 Prompt/策略/Secret |

### 4.2 权限动作目录（示例）

采用「资源 + 动作」便于 RBAC 与审计对齐：

```text
platform.tenant.create / suspend
platform.blueprint.read / write / publish
platform.model_provider.write

tenant.member.read / write
tenant.role.write
tenant.audit.read
tenant.feature.customization.toggle
tenant.quota.write

workspace.identity.read / write / publish / archive
workspace.skill.read / write / publish
workspace.tool_service.read / write
workspace.policy.write
workspace.grant.write          # 把智能体授权给用户/用户组
workspace.run.read_meta        # 脱敏摘要
workspace.run.read_content     # 正文，需额外条件
workspace.approval.decide

end_user.agent.use
end_user.session.read_own
end_user.run.read_own
end_user.artifact.download_own
end_user.memory.read_own / write_own / delete_own
```

### 4.3 决策伪代码

```text
allow =
  authenticated(principal)
  AND in_tenant_scope(principal, resource.tenant_id)
  AND has_role_action(principal, action, resource.workspace_id?)
  AND ownership_ok(principal, resource)          # 数据层
  AND policy_ok(tool/model, context)             # 运行层
  AND not_denied_by_quota_or_feature(principal)
```

四者缺一不可：**认证 → 租户边界 → 角色动作 → 数据所有权（+ 运行策略）**。

## 5. 资源模型与所有权

### 5.1 资源分层

```text
平台只读模板
  WorkspaceBlueprint@v
  IdentityDefinition → IdentityVersion
  SkillVersion / ToolOperation@v / PromptVersion（标准）

租户可变配置
  TenantWorkspace（pin blueprint version）
  TenantCustomizationOverlay（可选 CoW）
  TenantIdentity / 租户覆盖 Skill·Prompt
  IdentityGrant / Secret 引用 / 配额 / 策略覆盖

用户私有数据
  AgentSession / Message
  Run / TraceEvent / Artifact
  UserMemory
```

### 5.2 所有权字段（强制）

用户运行数据至少携带：

```text
tenant_id
tenant_workspace_id
identity_id? / skill_id?
owner_principal_id
session_id? / run_id?
```

唯一约束见 ADR / 技术实现文档。

### 5.3 共享边界

| 数据 | 默认边界 |
| --- | --- |
| Blueprint、标准 IdentityVersion | 平台模板层只读复用 |
| TenantWorkspace 配置 | 租户内按角色 |
| 租户知识库 | 工作空间共享，文档 ACL |
| Session / Message / Run / Trace / Artifact | 最终用户私有 |
| UserMemory | tenant + workspace + identity/skill + user |
| Secret | 工作空间/环境受控，永不下发最终用户 |

## 6. 企业扩展（定制）权限设计

### 6.1 功能开关

```text
tenant.features.workspace_customization = true | false
```

- `false`：仅能安装/引用平台已发布版本；可配授权、Secret、配额、策略覆盖。
- `true`：允许 Copy-on-Write 定制。

### 6.2 定制规则

1. **永不修改**平台 Blueprint / 标准 Version；
2. 首次改动创建 `TenantCustomizationOverlay`；
3. 改 Skill/Identity 时创建 **tenant-owned** fork/version；
4. 通过引用映射覆盖标准资源，不整树复制；
5. 每次定制可审计、可 diff、可回退到平台版本；
6. 升级平台 Blueprint 需预览差异，由 `tenant_admin` 确认。

### 6.3 配置解析顺序（运行时）

```text
Platform WorkspaceBlueprint Version
  → TenantWorkspace pinned base
  → TenantCustomizationOverlay
  → Environment override
  → Runtime policy + user-private state（仅影响本次上下文，不可回写配置）
```

### 6.4 定制相关角色协作

| 动作 | 平台目录管理员 | 企业 tenant_admin | customization_owner | 开发者 |
| --- | --- | --- | --- | --- |
| 发布标准 Blueprint | ✔ | — | — | 提交变更申请 |
| 安装 Blueprint | — | ✔ | — | — |
| 开启定制开关 | 策略允许时 | ✔ | 建议 | — |
| 创建租户覆盖版本 | — | ✔ | ✔ | 可起草，需发布权限 |
| 升级 pinned version | — | ✔ | 预览 | 影响评估 |

## 7. 智能体开发链路权限

### 7.1 生命周期与权限

```text
Draft ──submit──► Review ──publish──► Published ──archive──► Archived
                      │                     │
                      └── reject ───────────┴── rollback → 历史 Published
```

| 阶段 | 谁可写 | 谁可绑定/授权 |
| --- | --- | --- |
| Draft | agent_developer、ws_admin | 仅调试，不可 Grant 给员工 |
| Review | 提交人只读；reviewer 可评论 | — |
| Published | **不可变** | ws_admin 可 Grant |
| Archived | 不可新 Grant；历史 Run 仍可追溯 | — |

### 7.2 发布门禁（权限视角）

发布前检查至少包括：

1. Schema 与引用完整；
2. Tool 策略预览（allow/ask/deny）；
3. Secret 引用存在且未过期；
4. 模型 profile 在租户/空间白名单内；
5. 不包含未授权的跨空间资源；
6. 评测门禁（若启用）。

### 7.3 IdentityGrant（员工可见性）

```text
IdentityGrant
  tenant_id
  tenant_workspace_id
  tenant_identity_id | identity_version_id
  grantee_type: user | group | org_unit
  grantee_id
  granted_by, created_at, expires_at?
```

- 仅能 Grant **Published** 版本；
- 员工端「我的智能体」= 对本人 principal 解析出的 Grant 集合；
- 撤销 Grant 立即影响新建会话；进行中会话策略可配置为「允许收尾」或「立即拒绝」。

## 8. 企业员工使用权限

### 8.1 员工可见面

- 已授权智能体卡片；
- 本人历史会话；
- 本人任务（Run）与产物；
- 本人长期记忆的查看/纠正/删除；
- 个人设置。

### 8.2 员工不可见面

- 内部 System Prompt 全文与工具默认密钥；
- 他人 Session/Run/Artifact/Memory；
- 管理策略、配额、其他成员数据；
- 未 Grant 的智能体与草稿版本。

### 8.3 会话与运行

```text
POST /api/v1/me/identities/{identity_id}/sessions
→ 服务端校验 Grant + 绑定 Published version
→ 生成 session_id，写入 owner_principal_id（创建后不可改）
→ 所有后续消息强制校验 (tenant, workspace, owner, session)
```

流式订阅（SSE/WS）filter 由服务端按 Principal 生成，客户端不能订阅任意 `user_id`。

## 9. API 权限分层

### 9.1 路由前缀与默认策略

| 前缀 | 面向 | 默认鉴权 |
| --- | --- | --- |
| `/api/v1/admin/*` | 平台 | platform_* + MFA 建议 |
| `/api/v1/platform/*` | 平台目录 | platform_catalog_admin 等 |
| `/api/v1/tenants/{tenant_id}/*` | 企业与空间管理 | 租户成员 + 角色动作 |
| `/api/v1/me/*` | 员工 | 已登录用户，**禁止传他人 ID** |
| 现有 `/skills` `/runs` `/chat` | 兼容 | 必须挂 Principal 中间件后逐步收敛 |

### 9.2 中间件链

```text
TLS 终止 / WAF
  → Authentication（解析凭证 → Principal）
  → Tenant Membership
  → Workspace Grant（若路由需要）
  → Resource Permission（角色动作）
  → Data Ownership（仓储查询条件）
  → Application Use Case
  → Audit（写操作与敏感读）
```

### 9.3 查询模板（禁止先读后滤）

```sql
-- 正确
SELECT * FROM agent_sessions
WHERE tenant_id = :tenant
  AND tenant_workspace_id = :ws
  AND owner_principal_id = :principal
  AND session_id = :session;

-- 错误
SELECT * FROM agent_sessions WHERE session_id = :session;
-- 然后在应用层 if owner != principal
```

同样适用于 Run、Trace、Artifact、Memory、向量 metadata filter、Redis key、对象存储签名 URL 签发前校验。

## 10. 运行层权限（与 RBAC 正交）

RBAC 管「谁能配置/看什么」；运行层 Policy 管「这次执行能不能调这个 Tool / 用这个模型」。

| 控制点 | 说明 |
| --- | --- |
| Skill tools.allow | Skill 包级白名单 |
| Workspace/Identity 可见资源 | 路由与绑定解析 |
| Tool allow / ask / deny | global → tenant → workspace → identity → user 组合，明确优先级 |
| 审批 | ask 挂起 Run；审批人需 `workspace.approval.decide`；保持原 owner |
| 模型 profile 白名单与预算 | 租户/空间/智能体级 |
| Secret 注入 | 仅 Tool 声明的 secret_ref；不进 prompt/trace |

**默认策略建议（多用户生产）：** 无显式规则时，写操作与外发类 Tool 默认 `ask` 或 `deny`，不要全局默认 `allow`。

## 11. 管理员特权与「代查」

管理员**不因角色自动获得**用户正文读取权。

### 11.1 提权流程

```text
管理员发起 read_content
  → 校验 workspace.run.read_content 或 tenant.audit 配套权限
  → 必填 reason（工单号/投诉单）
  → 可选：二次审批 / MFA / 限时 claim
  → 返回最小必要字段（默认摘要，正文需显式）
  → 写入不可变审计事件
  → 不可批量顺带读取其他用户
```

### 11.2 聚合优先

运营看板只暴露：成功率、延迟、成本、失败聚类、脱敏样本。  
完整正文属于例外路径，不是默认路径。

## 12. 多租户数据隔离清单

| 位置 | 强制条件 |
| --- | --- |
| 关系库查询 | 所有 WHERE 带 tenant（+ workspace/user 按表） |
| 唯一索引 | 含 tenant（见 ADR） |
| 对象存储 | 路径前缀 `tenants/{tenant}/...`；下载短时签名 |
| 缓存 Key | `t:{tenant}:ws:{ws}:p:{principal}:...` |
| 向量检索 | metadata filter 必须含 tenant/workspace/user；缺 filter 拒绝 |
| SSE/WS | 服务端订阅 filter |
| 日志/Trace | 分级脱敏；禁止密钥与完整敏感 prompt |
| 前端 Query Cache | key 含 tenant+workspace+principal；切换作用域清空 |

**验收：** 用户 A/B 使用同一 IdentityVersion，任何可猜测 ID 均不能跨用户 200。

### 12.1 产出物目录模型（文件系统视角）

产出物（Artifact）在产品上按**个人网盘式目录树**展示，底层仍是对象存储 + 数据库元数据。

#### 逻辑路径

```text
tenants/{tenant_id}/
  workspaces/{tenant_workspace_id}/
    users/{owner_principal_id}/
      {identity_key | skill_key}/
        {yyyy-MM-dd}/
          {run_id}/
            plan.json
            plan-summary.md
            …
```

| 路径段 | 含义 | 权限含义 |
| --- | --- | --- |
| `tenants/{t}` | 租户根 | 跨租户一律不可见 |
| `workspaces/{ws}` | 工作空间 | 切换空间后旧缓存/URL 失效 |
| `users/{owner}` | **所有权边界** | 默认仅 owner 可列目录/读/下载 |
| `{identity}` | 业务智能体 | 便于用户按智能体归档 |
| `{date}/{run}` | 执行批次 | 对应 Run/Trace，可反查 |

元数据表建议字段：

```text
artifact_id, tenant_id, tenant_workspace_id, owner_principal_id,
identity_id?, skill_id?, run_id, session_id?,
logical_path, object_key, media_type, size_bytes,
created_at, expires_at, checksum
```

唯一约束：`unique(tenant_id, tenant_workspace_id, owner_principal_id, logical_path)`。

#### 访问决策（列表 / 预览 / 下载）

```text
allow_artifact(access, principal, artifact) =
  principal.tenant_id == artifact.tenant_id
  AND principal.workspace_scope_covers(artifact.tenant_workspace_id)
  AND (
        artifact.owner_principal_id == principal.principal_id          # 本人
     OR ( elevates(principal, artifact) AND audit(reason) )            # 管理提权
     OR ( platform_break_glass AND dual_control )                      # 破玻璃，极罕用
  )
```

**默认拒绝跨用户。** 管理角色（ws_admin / operator / tenant_admin）**不因角色自动获得**他人文件内容。

#### 提权读取（管理场景）

1. 管理员在产出物目录看到他人 owner 节点为「锁定」；
2. 点击「申请提权读取」，必填 reason（工单号）；
3. 服务端校验 `workspace.artifact.read_content`（或等价）+ 配额/频率限制；
4. 签发短时 elevate claim（如 15 分钟，绑定该 owner 前缀）；
5. 写入审计：actor、owner、path prefix、reason、结果；
6. 不可一次提权「整个租户所有用户」。

#### 列表接口语义

```text
GET /api/v1/me/artifacts?path=/            → 仅本人根目录（智能体文件夹）
GET /api/v1/me/artifacts?path=/发展规划助手/2026-07-28
GET /api/v1/tenants/{t}/workspaces/{ws}/artifacts?owner=
     → 仅管理元数据；默认不含 object_key 明文与预览
GET …/artifacts/{id}/download
     → 签发短时签名 URL；签发前再次校验 owner/elevate
```

前端目录树**不能**把他人 `object_key` 渲染成可点链接；锁定节点只显示存在性策略所需的最小信息（或干脆不展示）。

#### 下载与分享

| 机制 | 规则 |
| --- | --- |
| 本人下载 | Session 内授权 + 短时 URL |
| 他人下载 | 必须 elevate 或显式分享授权（默认无分享） |
| 公开链接 | 默认关闭；开启需租户策略 + 过期 + 水印/审计 |
| 保留期清理 | 到期删除对象与索引；审计保留删除事件 |

#### 与 Run / 会话侧栏的关系

- 会话右栏「本次产物」只挂当前 session/run 的文件；
- 目录树是用户全量产物的浏览入口；
- 二者同一套 ownership 校验，禁止侧栏绕过。

#### 原型对照

`prototype/web` 产出物目录页已实现：

- 按 owner 的目录树（员工只见本人）；
- 管理角色默认锁定他人目录；
- 提权需 reason，并写入审计列表；
- 预览/下载前二次校验；
- 路径展示与后端逻辑前缀一致。

## 14. 典型场景走查

### 场景 A：平台发布新模板

1. `platform_catalog_admin` 发布 `WorkspaceBlueprint@1.2.0`；
2. 各 `tenant_admin` 收到升级提示，预览 diff；
3. 确认后 `TenantWorkspace` pin 到 1.2.0；
4. 若租户有 overlay，系统提示冲突项需人工确认。

### 场景 B：企业定制发布智能体

1. `agent_developer` 在空间创建 Identity 草稿，绑定已发布 Skill/Tool；
2. `ws_admin` 发布 v1.4.2；
3. `ws_admin` Grant 给用户组「全体员工」；
4. 员工在工作台看到卡片并会话；
5. Run 记录 identity_version=1.4.2 与资源快照。

### 场景 C：员工 A 试图访问员工 B 的会话

1. A 使用 B 的 session_id 调 `/api/v1/me/sessions/{id}`；
2. 仓储条件含 `owner_principal_id=A` → 0 行；
3. 返回 404（不泄露存在性）或 403（若产品选择）；
4. 安全审计可选记录「越权尝试」。

### 场景 D：运营处理高风险审批

1. Tool policy=`ask`，Run → `waiting_approval`；
2. `operator` 打开审批队列，见最小参数与风险原因；
3. 批准后 `resume_run`，owner 仍为原员工；
4. 审批事件写入审计。

### 场景 E：管理员排查投诉

1. `tenant_admin` 仅见聚合失败率，点入需读正文；
2. 填写 reason，若策略要求则 `ws_admin` 二次批准；
3. 短时提权读取 A 的单条会话，审计双写；
4. 无法在同一流程批量拉取 B/C。

## 16. 实施优先级

### P0（多用户/Web 前置，必须）

1. Principal 与认证中间件；
2. `tenant_id` 贯通 RunContext 与存储；
3. Session owner 不可变 + 全链路 owner 过滤；
4. IdentityDefinition/Version 最小模型 + Grant；
5. `/api/v1/me/*` 与管理路由骨架；
6. 双用户越权自动化测试。

### P1（管理可用）

1. 角色与成员管理 API/UI；
2. 发布门禁与引用检查；
3. 审批 RBAC 与审计事件；
4. 正文读取提权流程。

### P2（企业扩展）

1. 定制开关与 CoW overlay；
2. Blueprint 升级预览；
3. 租户级策略覆盖与配额。

### P3（生产加固）

1. PostgreSQL/RLS 或仓储级强制；
2. KMS、对象存储签名、OTel；
3. 细粒度 ABAC/ReBAC（若组织树复杂）。

## 18. 安全默认值（建议）

| 项 | 默认 |
| --- | --- |

## 19. 总结

本基座的权限架构可以概括为：

```text
1. 平台模板与租户实例分离（复用 vs 隔离）；
2. Principal 是唯一访问主体，角色按平台/开发/扩展/员工四维建模；
3. 配置权在管理面，使用权在 /me，数据权在 ownership 字段；
4. 企业扩展用功能开关 + CoW，不污染模板；
5. 一切查询先租户后资源，一切敏感读先权限后审计。
```

实现顺序与字段/API 细节见 [技术实现文档_1.0.1](技术实现文档_1.0.1.md)；产品页面与验收见 [产品详细设计_1.0.1](../prototype/产品详细设计_1.0.1.md)。
